# ShareIt

**Сервис вещей «поделиться»** — микросервисное backend-приложение на Java и Spring Boot, где пользователи публикуют свои вещи, другие пользователи бронируют их на определённые даты, а если нужной вещи нет — оставляют заявку на её добавление.

---

## Архитектура

Приложение разделено на два сервиса: **API-шлюз** и **сервер бизнес-логики**.

```
                      клиент
                        │
                        ▼
        ┌───────────────────────────────┐
        │        shareit-gateway        │   порт 8080
        │  единственная точка входа API │
        └───────────────┬───────────────┘
                        │  
                        ▼
        ┌───────────────────────────────┐
        │         shareit-server        │   порт 9090
        │  бизнес-логика, JPA, хранение │
        └───────────────┬───────────────┘
                        │
                        ▼
        ┌───────────────────────────────┐
        │        PostgreSQL 16.1        │   порт 6541
        └───────────────────────────────┘
```

## Возможности

### Пользователи

| Метод    | Путь         | Назначение                          |
|----------|--------------|-------------------------------------|
| `POST`   | `/users`     | Создать пользователя                |
| `GET`    | `/users`     | Список пользователей                |
| `GET`    | `/users/{id}`| Пользователь по id                  |
| `PATCH`  | `/users/{id}`| Частично обновить пользователя      |
| `DELETE` | `/users/{id}`| Удалить пользователя                |

### Вещи

| Метод       | Путь                       | Назначение                                                          |
|-------------|----------------------------|---------------------------------------------------------------------|
| `POST`      | `/items`                   | Опубликовать вещь                                                   |
| `GET`       | `/items`                   | Список вещей текущего пользователя (с датами бронирований)          |
| `PATCH`     | `/items/{itemId}`          | Изменить свою вещь                                                  |
| `GET`       | `/items/{itemId}`          | Вещь с комментариями и датами ближайшего/последнего бронирования    |
| `GET`       | `/items/search?text=`      | Поиск доступных вещей по названию и описанию                        |
| `POST`      | `/items/{itemId}/comment`  | Оставить комментарий к вещи                                         |

### Бронирования

| Метод   | Путь                                  | Назначение                                          |
|---------|---------------------------------------|-----------------------------------------------------|
| `POST`  | `/bookings`                           | Забронировать вещь (создаётся в статусе `WAITING`)  |
| `PATCH` | `/bookings/{bookingId}?approved=true` | Одобрить или отклонить бронь владельцем вещи       |
| `GET`   | `/bookings/{bookingId}`               | Бронь по id                                         |
| `GET`   | `/bookings?state=`                    | Бронирования пользователя с фильтром по состоянию  |
| `GET`   | `/bookings/owner?state=`              | Бронирования вещей пользователя (как владельца)     |

**Статусы брони:** `WAITING` → `APPROVED` / `REJECTED`, `CANCELED`.
**Фильтры состояний** : `ALL`, `CURRENT`, `PAST`, `FUTURE`, `WAITING`, `REJECTED`.

### Заявки на добавление вещей 

Сценарий «нужной вещи нет» — пользователь оставляет заявку с описанием, а владелец вещи может в ответ привязать свою вещь к заявке.

| Метод | Путь               | Назначение                                                     |
|-------|--------------------|----------------------------------------------------------------|
| `POST` | `/requests`        | Создать заявку на добавление вещи                             |
| `GET`  | `/requests`        | Свои заявки (сортировка по дате убывания) + список вещей-ответов |
| `GET`  | `/requests/all`    | Заявки всех остальных пользователей                           |
| `GET`  | `/requests/{requestId}` | Заявка по id + вещи, предложенные в ответ                 |

### Шлюз: проксирование с сохранением контракта

Клиенты шлюза наследуют общий `BaseClient`, который:

- добавляет заголовок `X-Sharer-User-Id` ко все исходящие запросы;
- проксирует HTTP-метод, тело и query-параметры без ручного перечисления;
- **прокидывает ошибки проксируемого сервиса как есть** — `HttpStatusCodeException` перехватывается, и клиенту возвращается исходный код ответа и тело ошибки;
- собирается на `RestTemplate`, чтобы сетевые вызовы не занимали потоки Tomcat.

Маршрут на сервис задаётся одной настройкой — `shareit-server.url`:

```properties
# локально
shareit-server.url=http://localhost:9090
# в docker-compose
SHAREIT_SERVER_URL=http://server:9090
```

### Обработка ошибок

`ExceptionHandler` в сервере и в шлюзе переводит доменные исключения в HTTP-коды:

| Исключение | Код |
|------------|-----|
| Ошибки валидации | `400 Bad Request` |
| Объект не найден | `404 Not Found` |
| Дубликат e-mail | `409 Conflict` |
| Непредвиденная ошибка | `500 Internal Server Error` |

### Бизнес-правила

- **Бронь:** вещь должна существовать, быть доступна, принадлежать другому пользователю, а запрошенный интервал дат **не должен пересекаться** с уже существующими бронями этой вещи.
- **Одобрение брони:** только владелец вещи может одобрить или отклонить бронь.
- **Поиск вещей:** запрос по названию **и** описанию, без учёта регистра, только по доступным вещам.
- **Даты бронирования в карточке вещи:** `lastBookingDate` и `nearestBookingDate` — дата последнего и ближайшего бронирования.
- **Защита от N+1:** комментарии для списка вещей загружаются одним запросом и группируются в map по id, а не делаются по запросу на каждую вещь.

## Как запустить

Требования: **Java 21**, **Maven 3.9+**, **Docker + Docker Compose**.

```bash
git clone https://github.com/sellohay/java-shareit.git
cd java-shareit

mvn clean package        # собрать jar-файлы шлюза и сервера
docker compose up --build
```

| Контейнер | Адрес |
|-----------|-------|
| `shareit-gateway` | `http://localhost:8080` |
| `shareit-server` | `http://localhost:9090` |
| `postgres` | `localhost:6541` (БД `shareit`, пользователь `shareit`) |

### Пример запроса

Все запросы идут через шлюз — на `http://localhost:8080`:

```bash
curl -X POST http://localhost:8080/items \
  -H 'Content-Type: application/json' \
  -H 'X-Sharer-User-Id: 1' \
  -d '{"name": "Дрель", "description": "Мощная дрель", "available": true}'
```

## Тесты

```bash
mvn test
mvn -Pcheck verify
mvn -Pcoverage verify
```

**Тесты сервера**

- *Контроллеры* (`@WebMvcTest` + `@MockBean`): проверяются HTTP-коды, тела ответов и передача заголовка `X-Sharer-User-Id`;
- *Сервисы* (`@SpringBootTest` + `@Transactional`): проверяются бизнес-правила на реальной БД в памяти .

**Тесты шлюза** — `@JsonTest` на десериализацию DTO.
